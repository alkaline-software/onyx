# The window

About `crates/onyx-app/src/shell.rs`, `tabs.rs`, `ui_state.rs`, `main.rs`, `settings.rs`, and `crates/onyx-core/src/vault.rs`: the vault, a note's life, the tabs, the sidebar, the strip, the landing page, the sheets and menus, and what the window remembers.

## Rules

- **A note is written whole** (`vault::write`: a temp file beside it and a rename), never in place and never in part: a sync or another app reading the file sees the old note or the new one.
- **A note saves itself, as Obsidian's do.** Its first change since the last write marks it dirty and starts a timer (`Shell::note_changed`, `SAVE_AFTER`, two seconds); later keystrokes do not put the timer off, so typing without a pause is one write every two seconds, never one per keystroke, and no more than two seconds of words live only in the window. The timer finds its tab by its editor, which a rename keeps. A note is also written when another tab shows (`show_tab`), when the window is left for another app (`observe_window_activation`), when its tab closes (`close_tab`), before the vault closes or changes, when the window closes, at quit and before an update installs (`save_all`). A write whose text is what the disk has already is skipped (`save_tab`), so typing and taking it back costs nothing. There is no ⌘S and no dot on a tab: nothing waits to be saved by hand. (Obsidian 1.15's `TextFileView` does the same: a two-second timer that is not reset, a write when the editor loses focus, and none when the text is the last written.)
- **A note with changes is never replaced by the disk's text.** A note with none takes it whole and quietly (`Editor::replace_text_quietly`). A note with changes joins it with what was typed (`disk_text`, `onyx_core::merge::merge`): each side's changes are found line by line against the text last written or read (`Tab::saved`), every one is kept, and where both changed the same lines differently the window's come first and the disk's follow. The result goes in as one edit, one step of undo with the caret kept, is written at the next save, and is said under the strip quietly, in the muted ink with a merge icon (`say_quietly`), since it is news and not a failure; a failure is said in the danger's ink (`say`). Onyx's own write coming back from the watcher is nothing, since `saved` holds it.
- **A note or a folder deleted goes to the system's trash** (`vault::trash`), never `remove_file`.
- **A rename refuses a taken name** and a name with a slash, and keeps a note's extension (`vault::rename`); the open note follows its new path, and so does a note inside a renamed folder, and so does everything else that knows a note by its path (`Shell::rename_entry`: Wide, the last note shown, the closed tabs). Anything new kept by path goes there too. What must survive a rename is keyed by the note, not the path: a page's fade in is keyed by its editor (`render_page`), or a rename replays it.
- **The tree is read off the disk, never kept in step by hand.** After a change of Onyx's own, `reread_tree`; after another app's, the watcher.
- **The vault's folders of its own are not shown** (`.obsidian`, `.onyx`, `.trash`, `.git`, and anything that starts with a dot), and only notes (`.md`, `.markdown`) are listed.
- **Each tab has its own editor** (`Tab::editor`): the text, the caret, the scroll, the undo history and the dirty state stay with the tab while another shows, and a change to the faces, the size or the mode reaches every editor (`push_look`, `set_mode`). The editor's events name the tab they are for by its path, and a rename gives the editor a new listener under the new path. Tried and dropped: one editor handed each tab's text in turn, which lost the caret, the scroll and the history at every switch.
- **A size the next frame depends on is figured as the frame is built, never measured off the last one.** While a frame is drawn, gpui's `cx.notify` asks for no other frame (`invalidate_view` marks the window dirty only outside a draw), so what a canvas reads in prepaint waits for whatever draws next. With the pointer at rest after a window was resized by a key, nothing did: the tabs stayed at the old row's widths and place. The row's width and the page's come from the window's and the sidebar's (`Shell::render`).
- **Nothing under what stands over the window scrolls.** A sheet, the search, the viewer, a menu or a flown card says so as it is drawn (`Scrollers::over`), names its own scrollers with `name_over` (a flown card drawing the notes card lifts it, `Scrollers::lift`), and the scroll router gives the wheel to those alone, or to nothing; while a panel of the system's stands on the window as a sheet (the printing panel), nothing scrolls or follows the pointer (`sys::sheet_over`). The router hands the wheel to scrollers by their bounds, not gpui's hit test, so a new layer over the window that does not say so leaks the wheel to the note under it.
- **Everything the window remembers is written through `UiState`** (`save_ui`), never read from `Config`: the vault and the note are state, not settings.

## The vault

A vault is a folder. `vault::tree` reads it whole, folders first and then notes, each in the file manager's order (case folded, a number by its value, so Note 2 stands before Note 10), and the window keeps the result as `Vault::tree`. The folder is watched (`vault::watch`, the `notify` crate) from the moment it opens; the watcher's thread sends the paths that changed down a channel the window looks at every 300 ms (`watch_changes`), and a burst of them is one reading of the tree off the main thread (`disk_changed`). A note gone from the disk is closed.

Opening a vault (`open_vault`): the open note is written, the tree read, the folded folders of that vault put back from the window's state, the watcher started, and the vault put first among the recent ones (`UiState::remember_vault`, six kept). The system's folder picker is asked through `cx.prompt_for_paths` (`choose_vault`), from the landing page's pill, the sidebar's vault row, File, Open Vault… and ⌘⇧O.

A new vault (`start_new_vault`, from the landing page's primary pill, the sidebar's vault row and File, New Vault…) is a sheet: the name in a field, Notes to begin with, and where it goes as two rows. iCloud Drive puts it in Onyx's app library when the bundle is signed for one, else in an `Onyx` folder at iCloud Drive's root (`Shell::cloud_place`: `sys::icloud_container`, then `paths::icloud_drive`, `~/Library/Mobile Documents/com~apple~CloudDocs` on a Mac and iCloud for Windows' folder on Windows; the row is not shown where the machine has neither), so the system syncs it with no account of Onyx's own, as Obsidian's iCloud vaults are kept. On this computer puts it in a folder of the person's choice, the documents folder to begin with and the system's picker behind Choose…, for a vault that is also a git repository or anything else. ↩ or Create makes the folder (`vault::new_vault`, which keeps a folder of that name that is there already, so a vault synced from another machine is not refused, and refuses a file of that name) and opens it. What the app library takes is in `docs/platform.md`, iCloud Drive.

The watcher's changes are sifted before anything is read (`Shell::change_matters`): only a note, a folder, something gone that could have been one, and nothing under a dotted folder. A picture copied in, iCloud's bookkeeping and Obsidian's `.obsidian/workspace.json` cost no reading and no frame.

A wikilink names a note by its stem (`vault::resolve_link`): the link's own folder first, then the shortest path anywhere in the vault; a path with a slash is from the vault's root; a heading or an alias after `#` or `|` is dropped. A wikilink to no note makes the note at the vault's root, as Obsidian does (`open_wikilink`); one that names a file that is not a note (`[[plan.pdf]]`) opens that file with the system's app. A link that is a path is found as an attachment is (`vault::find_file`, below): a note of the vault opens here, any other file with the system's app; an address opens in the browser (`open_link`).

### The tree's choice and moves

The notes' tree is a list to work in, after Emaki's files panel (`shell/tree.rs`, `emaki/docs/panels.md`, Choosing rows and Moving).

- A click on a row chooses it alone and opens it (a note) or folds it (a folder); ⌘ and a click adds the row to those chosen or takes it out; ⇧ and a click chooses from the row last clicked to this one (`tree_click`, `Choice::anchor`). A press in the room around the rows lets the chosen go and starts a rectangle that chooses every row it reaches (`band_start`, `band_to`); every row is one height and the list starts at the scroller's top, so the rows are found by number. With none chosen the note showing is lit. A row is `TREE_ROW_H` tall and its lit plate stands `ROW_BREATH` in from its top and foot, so a row lit or under the pointer breathes apart from the next; rows chosen one under another drop that room where they meet and are one block, round at its two ends (`lit_joins`). The list starts `LIST_TOP` under the card's band. The press and the pointer are the row's whole height, its plate lit through a group (`tree-row`), so the room between plates is no dead line. The assets' rows are made the same way. A right click on one of several is their menu (Cut, Copy Paths, Move n Items to Trash); on any other row it chooses that row alone.
- The keys, while the keyboard is in the tree (`TREE_CONTEXT`, the click puts it there): ↑ and ↓ go from row to row, ⇧ with them grows the choice; → opens a folder or goes into it, ← closes it or goes up; ↩ opens the note; ⌘⌫ puts what is chosen in the trash, a folder chosen with what it holds once; ⌘A chooses every row showing; ⌘X cuts (drawn faint) and ⌘V moves what was cut into the folder the keys stand on; Esc lets the choice go.
- A row is dragged to move it, with the others chosen when it is one of them (`TreeDrag`, `drag_of`); let go over a folder it goes in, over a note into that note's folder, over the room around the rows to the vault's top, and the row under it is washed in the accent while it is held there. A row already there stays, a folder never goes into itself, and a name taken there refuses the whole move before anything moves (`vault::planned_moves`).
- A move keeps every link going where it went (`move_items`, `vault::move_into`, `vault::relink_moves`): a note moved keeps its own links, paths written again from its new folder, and the others' links to what moved follow, wikilinks with a path included. An open note's changes come from what its editor holds, as one step of undo written with the note; every other note's file is written whole. What knows a moved entry by its path follows it (`follow_moves`, which a rename goes through too): its tab, the note shown, the tabs closed, the folders folded.

### Assets

One folder at the vault's top holds every note's pictures and files, not one per folder as Obsidian can keep them: `.assets` (`vault::ASSETS`, `vault::assets`). It is dotted so that it is never a folder of the person's own of the same name, and so the tree and the watcher's sifting pass it by as they do `.obsidian`; the sidebar's Assets card shows it instead (below). A note made elsewhere that keeps its pictures in a folder of their own still finds them (`find_file`). Obsidian leaves dotted folders out of its index, so a picture in `.assets` does not show in Obsidian.

A file comes in by a paste (files copied in the Finder, or a picture copied alone, which is kept as `Pasted image <time>.png`) or a drop on the page, where the caret goes first (`Editor::attach`). It is copied into the folder off the window's thread under its own name or the first free one after it (`scan 1.pdf`), each name claimed by making it empty only where nothing is, so two coming in at once never share one, and filled through a temp file and a rename (`vault::copy_asset`, `add_asset`). A file in the vault already stays where it is. The note then refers to it in standard markdown, so any other app reads it (`vault::reference`): `![name](../.assets/a.png)` for a picture, `[name](../.assets/plan.pdf)` for any other file, the path from the note's folder with spaces and brackets as `%20` and their like, each a block with a blank line between it and the words on either side, on its own line or the next, so a picture is drawn here and elsewhere.

A link or an embed finds its file (`vault::find_file`) as written from the note's folder, then from the vault's top, then by its name in `.assets`, then anywhere in the vault outside a dotted folder by the shortest path, so Obsidian's `![[a.png]]`, a markdown path and `<img src>` all find the same file, and a note moved to another folder still finds its pictures.

The vault is the level above: a row of its own over the card (`render_vault_switch`), its mark, its name and the arrows of a list on a plate with the card's edge, so it reads as a choice and not as one of the rows that make things; a press opens the vault's list (New Vault…, Open Vault…, Reveal in Finder, Close Vault), and with no vault it says so and stands alone. Under it one card for what the vault holds (`render_side_stack`), its top a pair of tabs after a design of Emaki's: Notes and Assets, each half the width, an icon and a name, on a tinted track with a hairline under it. The one open stands on a plate, raised in the frame's own ink (`theme` is the frame's, `frame_theme`); a press on the other slides the plate across and the card's content fades in. Notes is open at first; the card open is remembered in `ui.json` (`side_view`). Tried and dropped: two icons alone on a segmented control, whose raised plate took the light theme's ink on the dark frame; the vault's name on the Notes card's band, which made the vault read as the notes; and a stack of cards after Emaki's computers, the one shut a row in a slim card at the sidebar's foot, which put the second of only two things far from the first.

The Assets card (`shell/library.rs`, `render_assets`) lists every file of `.assets` at any depth, but dotted ones (`vault::asset_files`), by its kind (`preview::kind`), a row each with the file's whole name, each group under its name and count: pictures first, each on a taller row (`PICTURE_ROW_H`) with its small square in the icon's place, cut from the picture's middle, drawn small off the window's thread once (`draw_thumbs`) and fading in when it arrives, large enough to tell one picture from another; then documents, media and the rest with their file icons. A grid of squares was tried first and lost the names. The list is read again off the main thread whenever the watcher says something in `.assets` changed (`assets_changed`, `reread_assets`). A press opens the file in a tab (`open_asset`); a drag puts its link in a note where it falls, as a drop of a file does (`AssetDrag`); a right click opens its menu: Rename, Open, Open with Default App, Reveal in Finder, Copy Link (the reference a note would write, from the note showing), Copy Path, Move to Trash.

An asset opens in a tab beside the notes, a tab like any other (`Tab::asset`): it takes its place in the row, its group is the `.assets` folder's pill (named Assets on its hover), ⌘W, ⌘⇧T and the tabs remembered across launches treat it as a note's, and `open_note` sends any file that is not a note to `open_asset`. Its name is the file's whole (`tab_title`). It is read only: its editor reads only (`Mode::Reading`), it is never written (`save_tab`, `note_changed` pass it by), and Print and Export are a note's alone; where a note's path bar has Export, an asset's has Open with Default App, except a picture's or a PDF's, whose frame has its own bar. The file is read off the main thread (`preview::read`): what can be read as markdown (text and code as a block of code, markdown itself, a table of CSV, a notebook, HTML, a Word document, a deck, a workbook's sheets) is drawn by the tab's own editor on a note's page, its title the file's name, its links followed as a note's (`render_note`); a picture and a PDF in the frame a note shows a PDF in (`Body::Frame`, `Embed::for_tab` in `embed.rs`), filling the page less its margin, its bar coming while the pointer is on it and fading as in a note (`Embed::settle_bar`, which the frame asks itself in a tab, with no note to ask it), over room of its own: the first page or the picture stands the bar's height and the margin down (`Embed::inset_top`), so the bar never covers the file until it scrolls. The bar holds the file's icon and its name, which a click renames as the note's bar does (every link following, and the tab, the path and the bar with it, `Asset::moved_to`); for a PDF the sidebar's button and the page it is on; the zoom as − 100% + (a press on the share goes back); for a picture View, which opens the viewer from where the picture stands, as a double click on it does; and the menu, the assets card's less Open (`show_asset_menu`). Nothing of a line is there: no place across the page, no width, no pencil. With no zoom chosen a file shows at 100% (a picture's pixel to a point, a PDF's page at its size in points, `preview::pdf_sizes`) or less, as much as the frame's width holds, never more, on the frame's ground with a margin round it; ⌘+ and ⌘- step through the frame's zooms and ⌘0 goes back, from the View menu too, as ⌘ and the wheel or a pinch zoom about the pointer. A picture is sized from its header (gpui gives a picture its own ratio, which wins over a box of the room's height) and stands as a PDF's one page does, so the frame's zoom and scroll serve both. A PDF has all the frame has in a note: every page drawn as it comes into view, its words selected and copied (read for the tab when it opens, `Embed::read_text`), the sidebar with its small pages and its outline or contents. The frame measures itself after each layout (`Embed::sizer`), as a note's frame has its row's size. a video or a sound in the system's own player (`media.rs`, after Emaki's `html_web.rs`: a web view set in the window over the page, shown once the page has faded in, and only while its tab shows with no menu, sheet, search or flown card over it, `sync_players`, since it is drawn over the window's drawing; its file handed out a range at a time under a scheme of ours that serves that one file; the keyboard is handed back to the window when it hides or goes, `sys::keys_to_window`; Linux has none and says so); anything else says why, with Open with Default App on it.

Renaming an asset (Rename on its menu or its tab's, the rename sheet as for a note, Rename File) keeps its extension and follows every link to it (`rename_asset`, `vault::relink`): a markdown link's or picture's address, in angle brackets or not, a wikilink's or an embed's target with its alias and size kept, and an HTML `src` or `href`, each written as it was (a bare name stays bare, a path stays a path from the note's folder, what follows `#` or `?` kept), and a link's words that were the old name become the new. A link counts as the file's when it finds that file (`find_file`), so the changes are found before the file moves. A note open in a tab is changed through its editor, from what the editor holds, as one step of undo written with the note (`Editor::apply_edits`); every other note's file is written whole (`vault::rename_asset`). Code is left alone.

## A note's life

`open_note` reads the file, makes a tab for it with an editor of its own (`make_editor`: the look, the mode, the text, and the listener for its events), puts the tab at the end of its folder's pill (`sort_tabs`) and shows it (`show_tab`), with the keyboard in its editor. A note already open just shows. The editor says when its text changed (`EditorEvent::Changed`), and the window writes it as the rules say. A new note asks its name first (`new_note_in`, `start_making`): the name sheet comes up as New Note with the first free "Untitled" in its field, selected to type over, and nothing is on the disk until Create or ↩ (`finish_making`, `vault::create`), which makes it under that name exactly, refused and said when the name is taken, and opens it; Cancel and Esc leave nothing behind. It goes in the open note's folder, else the vault's top (never `.assets`, when an asset shows). A new folder likewise. Made first and named after, a note cancelled at its name was left as `Untitled.md`. Both come from the sidebar's buttons, File, ⌘N and ⌘⇧N, or a folder's menu.

## The tabs

`tabs.rs` draws them; the shell holds them (`Shell::tabs`, in the row's order, and `shown`). As emaki has one tab per open session, Onyx has one per open note, and a folder's tabs stand together on one pill (`Tabs::group`, at every draw): the segmented control's track, with the folder's mark at its left end (its hover names the folder from the vault's root, or the vault) and the note showing on a raised plate. The pills are in the order their first tabs had, and a tab opened lands at the end of its folder's pill.

The plate is one element under a pill's tabs. It slides to another tab of the same pill, and between pills it fades out of one and into the other: a plate does not leave its track. It is placed by sum, never measured, since every width in the row is ours, and it reads the same clock the tabs' widths do (`Width::now`), so it keeps its tab while they move.

A tab is as wide as its name needs (`Tabs::sync`, at every draw): the title measured once in the tab's type at the showing tab's weight (`Tabs::fit`, by the theme's face, since the shell's render runs before any element's style is in force) plus the tab's edges, its close button and its outline, never under `TAB_LEAST`, a comfortable tab for a short name, nor over `TAB_MAX`. Once the row has no room for every tab at its own width, the widest give way first (`Tabs::share`): one cap is set so the row is filled, every tab wider than it is cut to it, and the narrow keep their width; the cap goes no lower than `TAB_MIN`, and past that the tabs keep their widths and the row scrolls sideways, with the tab shown brought into view; the row is centered while the tabs and the plus fit, and runs from the left once they do not, which is a padding of ours (`Tabs::lead`) and not the row's own centering, so it can move. A new tab grows in from nothing while the others give way, a closed one's room is taken up the same way, and a new pill's track is let out with its tab, each over `TAB_ANIM`. Whatever changes the row's room, a window resized or the sidebar moved, every width, the lead and the scroll that brings the tab shown into view head for their new values from where they stand (`Width::head`, `TAB_ANIM`), so the tabs glide; asked again at every frame of a drag, they follow it and catch up when it stops. The window asks for a frame while anything in the row moves (`Tabs::moving`). A width's animation element keeps its id through all of this: it is there to read the clock, and a new id at each step would lose a press on a moving tab. Tried and dropped: the flex row sizing tabs to their titles and shrinking them itself, which drew a new tab at full width for a frame.

A tab is dragged along its pill and a pill along the row by its handle, the folder's mark, with the name on a ghost under the pointer and the one being moved drawn faint (`DragTab`, `DragPill`, `Ghost`; the row's `on_drag_move` hears both). The tab or pill stands after every neighbor whose middle the pointer has passed (`drag_tab_to`, `drag_pill_to`): going by the middle keeps two of different widths from changing places back and forth under a pointer that is still. The one tab of a pill takes the pill with it. Each neighbor that changed places slides to its new place from where it is now (`Shift`), the plate going with the showing tab, and the pill being moved is painted over the ones it passes (`deferred`). The row's new order goes to the shell (`Shell::reorder_tabs`), which keeps `Shell::tabs` in it and remembers it; `Tabs::group` keeps a drag's order since pills stand in the order their first tabs have. A press on a tab or a handle is the start of its drag, not the window's (`press_taken`, below).

⌘ held alone for half a second shows each of the first nine tabs its number on a small plate half over its lower edge, with an outline on every tab, and they go when the key is let go or another joins it, so a quick ⌘C never sees them (`Tabs::modifiers_changed`, from the shell's `on_modifiers_changed`; a release the window did not hear, after ⌘Tab away, is caught at the next draw). A probe shows them with `ONYX_GO=hints`.

A tab's close button is at its right. ⌘W closes the tab showing and the next one shows in its place, then with no tab left the vault's page; on the vault's page with tabs still open it gives way to the tab shown last (`last_shown`, kept by `show_home`), or the row's last, and only on the page with no tab open does it close the window (`close_nearest`; `main.rs` closes any other window, the settings, on a ⌘W no view claimed). ⇧⌘W is the window straight away. ⌘⇧T opens the tab closed last again, and at each further press the one closed before it, passing over a note gone since or open again (`closed_tabs`, `reopen_tab`). ⌘1 to ⌘9 go to that tab in the row's order, or the last when there are fewer (`go_tab`). The open tabs, their order and the one showing are remembered (`UiState::tabs`, `note`) and open again at launch.

## The sidebar

`render_sidebar`, after emaki's, on the frame with the frame's inks whatever the appearance (`frame_theme`): the title row with the app's icon and the wordmark at its right, the window's to drag by; the New Note row with its accent disc and the New Folder row under it, each with its key at the right; the vault's row and its card, Notes with the tree or Assets (`render_notes_card`, The vault, Assets); and the foot with the person's picture (`avatar`: the picture chosen in Settings, Appearance, cut square and kept at 512 and at each size it is drawn at, or their initial on the accent), their name in the wordmark's face (`name_of`: the settings' own, or the account's first name) and the settings' gear, which wears a dot in the accent at its top right while a newer Onyx waits, as About does in the rail, so an update is seen with the settings shut (`waiting_dot`). The sidebar's button and the search's stand beside the traffic lights, drawn once over the window (`render_strip`), so they do not move with the sidebar's content.

**Folded, the sidebar is a rail** (`render_rail`), as emaki's: a column `RAIL_W` wide at the window's left with the traffic lights stacked at its head on a Mac (`sys::fold_lights`, called at every draw with how far the sidebar is, which moves the system's buttons between gpui's row and the column and puts them back whenever gpui moves them), then the sidebar's button and the search's a size larger, a rule, the New Note disc, the notes card's button, and at the foot the app's icon and the person's picture. The notes card's button flies the card out beside the rail over the page (`render_rail_fly`), for a note picked without the sidebar; a press beside it, Esc or a note shown lets it go. The sidebar's column grows from nothing to its width on one eased clock (`side_t`, `SLIDE`) while the sidebar itself stays put and fades in over the last part of the way; the rail fades out over the first part; the two buttons and the lights slide between their two places; and the card's left edge waits at the rail's until the column is past it. Nothing slides sideways but what the two states share.

**Its width is the person's** (`sidebar_w`, kept, `SIDEBAR_W` to begin with), after emaki's: a strip `SIDEBAR_GRIP` wide over the sidebar's edge (`render_side_grip`) lights a line under the pointer and takes a drag, which sets the width to where the pointer is between `SIDEBAR_MIN`, room for the lights, the two buttons and the name, and `SIDEBAR_MAX`. Left of `SIDEBAR_FOLD_AT` the sidebar folds to the rail, and brought back out in the same drag it opens again. The strip stays on the rail's edge while the sidebar is folded, so a drag from there past `SIDEBAR_FOLD_AT` brings it out, and a double click opens it at the fitted width. A held edge is heard in the capture phase, so it follows the pointer wherever it goes and nothing under it hears the move. A double click goes to the width at which the tree's rows in view are not cut (`sidebar_fit`), from `SIDEBAR_MIN` to `SIDEBAR_FIT_MAX`, so one long name does not ask for the most, over `SLIDE`. The notes card flown out from the rail is the same width.

The tree is `render_tree`: the vault's tree flattened into pieces (`tree_pieces`), a row for each entry and an open folder's children after its row, and only the pieces in view are drawn (`TREE_OVER` rows beyond the list's box at either end); the rows above and below stand as one empty box each, of their height, so the list keeps its length and the scroll its place. Every row is `TREE_ROW_H` tall, so where each stands is a sum and nothing is measured, and a vault of a thousand notes costs the frame no more than the rows in view. The list's box and offset are read off `side_scroll` as last painted; before the first paint, `TREE_FIRST` of the tree is drawn from its top. A folder's children on their way in or out are one piece, a fold (`Piece::Fold`): a box that runs up to their height and back, the content fading with it, keyed on the folder's path so each change plays once and the first sight plays nothing (`Motion::presence`, with `Motion::progress` for how far the box has run, so what stands below it is placed right while it moves). The folded set is `Vault::folded`, remembered per vault. A row (`render_row`): the chevron (a folder), Catppuccin's icon, the name, ended with an ellipsis where it does not fit, on a plate while it is the open note. Every row and every fold is `flex_shrink_0`: a scroll box's children shrink to fit it otherwise, and a tree taller than the sidebar drew its folders empty and its rows squeezed. Tried and dropped: a canvas measuring each fold's children, and every row of the vault drawn at every frame, which cost a frame some 16 µs a note, visible or not. A right click opens the row's menu (`entry_menu`): a note's is Open, Reveal, Copy Path, Rename…, Move to Trash; a folder's is New Note, New Folder, Reveal, Rename…, Move to Trash.

## The strip, the path bar, the source and the terminal

The strip is the card's top: the tabs in the middle, clear of both ends by `STRIP_GAP`, and after the last of them a square on a track of its own with a plus on it (`PLUS_W`, drawn with the row), whose press is New Note (its hover says New Note and ⌘N), in the folder of the note showing as ⌘N's is; a plus that showed the vault's page, under a hover that said Home, read as nothing a plus means and was dropped, and the page shows when no tab is open; the row keeps its room in the width it shares out, and with no tab open there is no row and no plus, since the page is showing anyway. Tried and dropped: the tabs from the left with a home tab before them, which left the strip lopsided. The strip is the window's to drag by (`drag_region`): a press on it moves the window once the pointer moves with the button down, unless a tab, a pill's handle or a button took the press first (`press_taken`, set by a child's mouse-down listener, which runs before the strip's), and a double click is the title bar's.

Under the strip the card turns to the page's tint (`page_ground`: the card's color under the muted shade at 0.3), one ground for the path bar, the find bar and the page with no line between them, so the sheet's edge is the one line below the tabs. The card paints no ground of its own: the strip rounds its top two corners and the tint its bottom two, at `CARD_R`, because `overflow_hidden` clips to a square and whatever paints square into a corner shows there. On the tint runs the path bar (`render_path_bar`), after emaki's path line, a row of `PATH_BAR_H` with no ground or line of its own and the path alone in its middle: the note's name with its folder before it from the vault's name, in code's face, or the vault's own place while its page shows (`sys::short_path`: from `iCloud Drive` for a vault there, else from `~`), a chip whose press reveals it in the file manager. Tried and dropped: a band for the path with a hairline above and below, which with the sheet's edge put four lines in the top 120 of the card; the ways of showing and the widths on this bar, which said they belonged to the note showing.

The ends of the tabs' row (`render_strip_ends`) hold two buttons after Emaki's panel buttons (`toggle_button`): at the left the note's source (`icons/file-code.svg`, a note's only), at the right the terminal (`icons/terminal.svg`, while a vault is open, or while it shows). Each is its icon alone, gray and washed under the pointer, in the ink while it is on, with a short line of the accent under it that grows out from its middle and shrinks back (`pressed_line`, keyed on the press's number so each press plays it once). The row's squares keep as much room from the card's side as from its top and foot (`STRIP_END`, the row's height less the square's, halved): more at the side read as a margin of its own. The source is the app's own and not a note's: only the person changes it, a first launch has it off, and it is kept (`UiState::source_open`; the modes, the three widths and the full width of earlier builds are passed over in an old file). The terminal is not kept past a launch, as its shells are not; its width is (`term_w`). They fade as they come and go, and both ends keep their width with or without them, so the tabs keep one center line. ⇧⌘S and ⌃` press them (⌃` as VS Code's terminal has it: ⇧⌘T is Reopen Tab), and the View menu names both. Tried and dropped: three ways to see a note (as it reads while written, as it is written with its styles, as it reads only) and three widths, each a capsule that opened into its group of three; then a Full Screen button for the width, which nobody needs to choose once the width follows the panes (The sheet and its width).

**The source pane.** With the source on, a note's page is two: the source at the left, a sheet as the note's is, the full height of the page with `SHEET_MARGIN` of the tint round it, and the note's own page beside it (`render_source`, `source.rs`, `docs/editor.md`, The source). The pane takes a share of the card, half at first (`source_share`, kept), never less than `SOURCE_LEAST` and never leaving the note less than `NOTE_LEAST`; in a card too narrow for both it is half. The edge between them takes a drag as the sidebar's does, a line of the accent lit on it under the pointer, and a double click shares the card half and half again (`render_source_grip`, `source_drag_to`). The share is of the room beside the terminal (`source_room`, the card less the terminal at that frame), as the pane is drawn: measured against the whole card, the edge jumped left of the pointer by the terminal's share as the drag began. The pane comes and goes over `SLIDE`, widening from nothing and fading in, its words laid out at the width it has all the way out so they do not wrap anew as it slides, and the note's page beside it refits as it goes. The page's width is the card's less the pane's at that frame (`page_w`), figured as the frame is built. Each note has a pane of its own, made the first time it shows and kept with the tab (`Tab::source`), with its caret, its scroll and its history. The keyboard goes with the button: in the note as the pane opens, it goes to the same place in the source; in the source as it goes, back to the note there (`toggle_source`, `Editor::caret_byte`, `put_caret_at`). An asset has no source.

**The sheet and its width.** A note is a sheet on the page (`render_note`): a column of the card's ground with a hairline round it on the page's tint, which runs up under the path bar to the tabs' row, with `SHEET_MARGIN` of the tint showing round it, so the words' room and the margins read apart; the words stand `SHEET_GUTTER` in from the sheet's edge at every width. It has two widths (`sheet_width`): its own, halfway from `READ_W`, a comfortable line of reading, to the page's edges, as far as `SHEET_MOST`, so a big monitor does not stretch it; and full, to the page's edges less the margin. Nobody chooses between them: the sheet is its own width while it is alone on the page, and full while a pane stands beside it (the source, the terminal), where the page is narrower. Its own width is figured from the page and not fixed, so on a laptop it uses the room and on a big monitor it stays a line to read. A page no wider than `READ_W` has room for one width, and both are it. The gutter is one at both widths: wider at full width, as it once was, a full sheet in a page no wider than its own width had less room for its words than the sheet it replaced. A change moves with the pane that caused it, along a level from its own width (0) to the page's (1) (`width_level`, the larger of the source's and the terminal's place in their slide), the words wrapping as they go; the page's width is figured as each frame is built, from the window's, the sidebar's and the source pane's (`page_w`), never measured from the frame before, which left the sheet a frame behind a window being resized and then a moment more until the next draw. The find bar is the sheet's width.

**The terminal.** ⌃`, the View menu's Terminal and the strip's right button show the vault's shells at the page's right (`terminal.rs`, `TermPanel`), taken from Emaki's shell terminal with its look, its keys and its pointer (Emaki's `docs/channels.md`, The terminal panel, has each in full). It is a sheet as the source's is, on its own ground, under the path bar (a clip is square, so nothing in it lays a ground that reaches a corner: the panel and its head lay none and the sheet's shows through, and the first tab rounds its own top left corner by the sheet's radius less its border, `SHEET_R`; a ground of their own stood square past the sheet's curve), `term_w` wide (520 to begin with, never under `TERM_LEAST` nor leaving the note `NOTE_LEAST` and the source `SOURCE_LEAST`; in a card too narrow for it and the note, each takes half). In a card too narrow for the source, the note and the terminal at their least, the pane asked for last shows and the other gives way, as Emaki's panels do (`term_latest`, `panes_fit`, `source_shown`, `term_shown`): its button's line goes out with it, it comes back when the card has room again, and a press on its button brings it back in the other's place. Tried and dropped: a third of the card each, which cut the shell's rows and wrapped the source a word a line. Its edge takes a drag and a double click as the source's does (`render_term_grip`, `term_drag_to`). It comes and goes over `SLIDE` as the source does, drawn at its full width as it slides, so the shell keeps its columns; put away, it is drawn as it was while it goes, with nothing started, sized or measured for it (`TermPanel::set_shown`). It is made the first time it is asked for and kept, with its shells, until the app quits (`Shell::terminal`); a vault opened since is where its next shell starts (`set_cwd`).

- **Shells.** The person's login shell in the vault's folder (their home when that is gone), started so its prompt marks itself (`onyx_core::shell_marks`, OSC 133), a tab each in its head: the first is made when it is first shown, + makes another (⌘T, ⌘N), a tab's button closes it, ⌘W closes the tab showing and with none left puts the terminal away (`TermEvent::Away`). A tab is pressed to show it, the screen fading in over the one before, dragged to move it, and grows in when new; ⌘⇧[ and ⌘⇧] go along them. A shell gets no `ONYX_*` variable, so a probe's vault never reaches a relaunch from it, and a UTF-8 character type where the app has no locale (one opened from the Finder has none): without it zsh counted é and 世 as several columns and drew the cursor off its letters.
- **The screen** (`onyx_core::pty`, `vendor/vt100`): Kaku's scheme for the window's appearance or the one chosen, the window's code face with Kaku's fallbacks at 13, a row 1.32 × 1.15 of the letters, 15 of room round it; a resize reflows the shell's lines; a pty writes from its own thread, so while the terminal shows a task looks every 33 ms and draws again when the screen changed (`watch`).
- **Keys** are Emaki's: a Mac's terminal keys (⌥ and ⌘ with arrows and Backspace, ⌘K clears, ⌘A the paragraph being typed), what is typed edited as a field's text by steering the shell's cursor, Shift with the keys that move a caret selecting, the keys that scroll back. Tab and ⇧Tab are the shell's (`TERMINAL_CONTEXT`); off a Mac every Ctrl and a letter is the shell's.
- **The pointer** is Kaku's: a drag selects (a double click the word, a triple the row, ⌥ the same columns of every row) and is followed anywhere in the window, scrolling at the screen's edges; the selection is copied when the button is let go, with "Copied" shown; a click that selects nothing puts the cursor there; ⌘ and a click opens a link or a file; the middle button pastes; the right one opens the window's menu (Copy, Paste, Select All, New Tab, Close Tab, Clear: `menu_do`). A program that asked to hear the mouse hears it, unless Shift is held. Files dropped on it are typed as their paths, and a picture pasted is kept in the cache and pasted as its path.
- **Settings, Terminal** (`TerminalConfig`): the scheme, the cursor's shape and whether it blinks, ligatures, and copying a selection when the button is let go; the face is the code face, set in Text, Fonts.
- **Find** (⌘F on the screen, `find_open`): a card at the screen's top right as the note's find bar is drawn, looking through the screen and all it keeps of what has left it (`find_run`), without regard to case unless what is looked for has a capital. Every match is washed in the cursor's ink, the one that stands stronger; a new phrase stands on the newest match, the one nearest the prompt, brought into sight a third down the screen (`find_show`). ↩ and ⌘G go to the next, ⇧↩ and ⇧⌘G to the one before, round the ends; Esc, the close button or ⌘F in the field closes it and gives the keyboard back to the screen. A selection on the screen is what it opens looking for. While the screen changes the matches are looked for again, at most every 300 ms. Emaki's terminal has no find; this one is Onyx's own.
- **An input method composes in place.** A letter, a mark or a space is not a key here: the screen's key listener lets it go, and gpui gives it to the input method, which composes it (`replace_and_mark_text_in_range`, drawn at the cursor, underlined, in the cursor's place) or types it (`replace_text_in_range`, sent to the shell, in place of what is selected of the line being typed). The input handler is the screen's while it has the keyboard (`ElementInputHandler`, registered at paint), and the candidates stand under the cursor (`bounds_for_range`). Off a Mac, Alt with a key stays the shell's meta key. Emaki's terminal took letters as keys, and Chinese or Japanese could not be typed there.
- **A gesture stays on the screen.** The screen scrolls by its own count of rows back, so it names itself to the router with what moves it (`Scrollers::name_own`, `scroll.rs`): a flick begun on it moves it alone, its momentum carried onto the note or the source included, and one begun on the note never moves it.

**The note's name** stands over its words, a soft line under it (the border at 0.7), and it is the file's name, so typing there renames the file (`make_title`, `keep_title_at`). It is a `Textarea` of the tab's own, as the editor is, set `flush` so it lines up with the words, and it wraps as long as `TITLE_ROWS`. ↩ keeps the name and goes to the words, and so does the keyboard leaving by any other way; closing the tab keeps it first (`close_tab`). Esc puts the file's name back and goes to the words (`drop_title`). A name that cannot be used (a slash, a name taken, nothing) puts the file's name back, with a notice where there is something to say. A line break, from ⇧↩ or a paste, is a space. On a locked note (a file's tab that reads as words) it is plain words drawn alike. gpui tells a field it lost the keyboard after the frame that moved it, when another note may be showing, so the event finds its tab by the field (`keep_title`), never by the note shown. A new note's name still comes up in the rename sheet.

**A scroller's edges** (`edge_fade`, on the note, the notes card and the landing page) fade into the ground beneath while there is more beyond, whole with `FADE_ROOM` left to scroll and none at the end (`fade_strength`). What is under a fade counts as out of sight, as if a hard edge stood there, and the fade only lets the words show: the zone takes no press and no hover (a hitbox that blocks all but the wheel, so a scroll over it still works, and the scrollbar is drawn after it and stays on top), and its height follows the fade's strength, so what reads whole is live. It holds at both ends alike. A fade standing in a rounded card rounds its own foot to that card's radius (`corner`), or it paints the corner square. `FADE_H` is the editor's `SCROLL_MARGIN`, which keeps the caret out of it (`docs/editor.md`); change the two together. The fade is a canvas set after its scroller and reads the handle as it is placed: a scroller's length is known only once it is laid out, so read in `render` it is a frame late and missing from the first frame of a long note.

**The find bar** (`render_find_bar`, ⌘F, Find… in the Edit menu) slides in under the path bar over the note: the phrase in a field, how many matches and which, and the way to the next (↩, ⌘G) and the one before (⇧↩, ⌘⇧G), round the ends; Esc, the close button or ⌘F in the field closes it. The editor finds every place the phrase is (`Editor::set_find`, with `search::find_all`, found again after each edit), washes them all and stands on one, which is the selection, scrolled into view; the one stood on begins at the first match at or after the caret.

**The search** (`render_search`, ⌘K, Search… in the View menu, the magnifier beside the traffic lights) is a palette over the whole window, as emaki's: a field, and under it the notes the phrase is in, the ones named by it first and then by how often it is in them, each with its folder, its count and its first lines with the phrase marked (`onyx_core::search`, every note read and looked through off the main thread at each keystroke, the newest search winning, since a vault keeps no index). ↩ opens the first, a press any one, with the phrase in the note's find bar; Esc or a press beside the card closes it.


## The landing page

With no vault: the name in the name's face and the accent, one sentence, two pills (New Vault… as the primary, Open Vault…), and the recent vaults on a card. With a vault and no note (`render_no_note`): emaki's home page with Obsidian's new tab on it. The drawing (`home_figure`) is the icon's own picture, after emaki's handscroll: a notebook on a tile of onyx, a thin cut slab seen from above and a little to the left with its thickness at the front and a vein of the band's teal across its top, and a pen by it. A picture is painted in one color, so the drawing is layers of one color each, in the icon's own colors whatever the accent or the appearance: the tile's base, sides, top, vein, glint and shadow, the notebook's pages, cover, lines and bright line; the pen is one color, the lines' gray in the light appearance and the pages' warm white in the dark (the window's foreground was tried and was too hard beside the picture), so it shows on either ground, with its nib's slit in the paper's and an edge in the ground's color under it, so it stands off the tile and the lines it crosses. The tile's and the pen's layers are pictures in `icons/home/` (a face's corners are rounded by a stroke of its own color); the notebook's five are made as text at each draw with its tilt written in, rounded to half a degree, and handed over as data (`svg().data`), since gpui turns a picture only after it is rasterized and a line turned that way blurs; each tilt is rasterized once and kept by its text's hash. It answers the pointer on a spring (`widgets::Fig`, emaki's `HomeFig`, with a third value for how near the pointer is): the notebook tilts and lifts toward it, the pen comes to the page and writes the bright line as far as the pointer has come across, then goes back to lie by the stone with the line whole, and the window asks for a frame while the spring moves. Under it the greeting by the hour and the account's first name (`greeting`, `sys::user_first_name`), in the note's face so the page and the note agree, and then what can be done next on pills with their keys at the right: New Note, New Folder, Reopen Closed Tab while there is one, Open Vault…. Each page fades and rises in (`page_in`) when it arrives.

## The sheets

`render_sheet` draws one: a card over a scrim with a title, what it asks, its pills and a line of keys; Esc or a press off the card lets it go, and the card occludes, so a press in it let go outside does not close it. Each sheet's name is in the toolkit's `Input` (`rename_input`, `vault_input`, each made with the window, since an input watches the window it was made in), and ↩ keeps it through the input's `PressEnter`. The rename sheet (`render_rename`) and the new-vault sheet (`render_new_vault`) are the two of this kind, and the export sheet (`render_export`, `docs/export.md`) is drawn on the same scrim, wider, with the page in it; one is up at a time. After a sheet the keyboard goes back to the editor when a note is open, else to the window.

## The settings

`settings.rs`, the studio's window: a rail of three sections, the page at the right, drawn from the main view's state so a change shows in both windows. Appearance has the appearance and the accent, and the language at the right of its title. Text is two pages, chosen at the right of its title (`settings_page`): Fonts, the note's face as serifs over sans serifs, code's face and the Chinese face, each on a tile drawn in itself (`fonts_rows`, emaki's Text page), with a field under each card for a font installed on the Mac (`font_inputs`, made with the settings window and listened to for a change; a tile chosen clears the field over it); and Size (`size_rows`), a preset for both places at once (Small, Medium, Large, Custom: `EditorConfig::text_size`, `TextSizes`) with each place's size under it on a stepper, which only Custom moves, and a button back to Medium's beside a size that left it, then Readable line length. Custom's own sizes are kept while a preset is chosen (`EditorConfig::sizes`). About has the title card, Alkaline Software presents with the studio linked, and the updates. A change to a face or a size reaches every editor through `Shell::push_look`.

## What the window remembers

`ui_state.rs`, `~/.onyx/state/ui.json`: the bounds (from `window_bounds()`, never `bounds()`), whether the sidebar is open and how wide, the settings' section, the vault, the note, the mode, the notes shown wide, the recent vaults, the folded folders, the folder the last PDF went to. Written when any of it changes (the bounds at most every two seconds), at quit, and when the close button closes the window. The writing is a thread's own (`UiState::save_later`, `Shell::save_ui`), the saves in the order asked: `write_atomic` flushes the file to the disk, some 5 ms on an SSD, and a frame is not to wait on that for a tab moved mid-drag or a folder folded. What was last asked is kept and is what `UiState::load` gives, so a state read, changed and written again never misses one still on its way. The window's close (`Shell::save_ui_now`) and the app's quit (`UiState::flush`) wait for the disk, since on Windows and Linux the close ends the app.

## Probing

`ONYX_VAULT=<folder>` opens that vault instead of the remembered one, `ONYX_NOTE=<file>` that note; `ONYX_GO` steps: `note` (the first note), `notes` (the first three, as tabs), `close` (⌘W), `sidebar`, `menu` (the first note's menu), `rename` (its rename sheet), `vault` (the new-vault sheet), `live`, `source`, `reading`, `end`. With `HOME` pointed at a scratch folder the sheet finds no iCloud Drive and makes the vault in that folder's `Documents`, so a probe can press ↩ without touching the person's iCloud. `ONYX_SETTINGS=text` opens the settings on that section (`docs/probing.md`).
